이 포트폴리오에 맞는 윤문 원칙을 참고했다. 확인한 README의 버전은 2.3.2다.
플러그인을 설치하거나 실행한 것은 아니며, AI 탐지 점수나 자동 윤문 등급을 주장하지 않는다.

## 문체

추상적인 구호보다 어떤 일을 맡았고 무엇을 바꿨는지 쓴다.
“경계를 연결했다”, “경험으로 전환했다” 같은 표현은 실제 작업으로 풀어 쓴다.
문장 길이를 억지로 맞추지 않고 불필요한 쉼표와 영어 광고 문구를 줄인다.
기술 용어는 유지하고, 자연스럽게 보이려고 일화나 감정을 만들어 넣지 않는다.
포트폴리오에 맞는 존댓말을 유지한다.

## 변경 범위와 사실 보존

첫 화면 설명, 강점, 프로젝트 제목과 요약, 사례 소제목과 마무리, 연락 문구를 수정했다.
사용자가 선택한 “원래 이렇게 해요” 헤드라인은 그대로 유지한다.

`src/content/portfolio.mjs`의 회사·경력·수상·기술 목록과 프로젝트의 식별자,
기간·진행 상태·역할·기술·성과 수치·링크·사례 본문 문단은 원본과 동일하다.
실무의 Vue·Spring Boot 경험과 개인·CoP의 React·TypeScript 경험을 구분한다.
개발 중인 프로젝트를 완료한 성과로 바꾸지 않는다.

카드·목록·상세 요약·메타 설명은 같은 `summary`를 사용한다.
`tests/copy.test.mjs`는 원본 main의 사실과 사례 본문을 해시로 비교한다.
실제 경력이나 성과가 바뀌는 후속 수정에서는 근거를 검토한 뒤 테스트 기준도 갱신한다.
