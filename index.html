Vue 라우터 lazy-load의 변수 기반 동적 import가 Webpack context 모듈을 만들어 폴더 전체를 스캔하고 파싱하던 구조를, 정적 경로와 고정 청크명으로 리팩터링해 풀빌드 시간을 5분대에서 1분대로 단축한 프로젝트.

Background / Problem
  • 라우터 lazy-load에서 변수로 경로와 청크명을 구성해, Webpack이 context 모듈을 생성하고 해당 폴더의 모든 후보 파일을 스캔하고 파싱
  • 풀빌드에 약 5분이 소요되고, 청크 경계와 이름이 자주 바뀌어 캐시 적중률이 낮음
Solution / Process
  • 변수 경로 동적 import를 정적 파일 경로로, 변수 섞인 청크명을 고정 webpackChunkName으로 통일해 정적 분석이 가능하도록 변경
  • 라우트별 독립 청크 그래프를 안정화해 모듈 스캔과 파싱량, 해시 변동을 최소화하고 캐시 적중률 상승
  • 동적 페이지가 필요한 경우 화이트리스트 매핑 객체로 한정된 집합만 로드하도록 제한
Result
  • 정적 분석이 가능해져 필요한 파일만 빌드하고, 캐시 적중률 상승으로 재빌드 시간 감소
  • 풀빌드 시간 약 80% 단축 (5분대에서 1분대로), 하루 수차례 배포하는 팀 전체의 대기 시간 절감
  • 배운 점: 번들러의 동작 원리(context 모듈, 정적 분석)를 이해하고 근본 원인을 제거하면 큰 성능 개선으로 이어진다는 점
Period

Tech Stack

SBOM 기반 사내 오픈소스 취약점 관리 플랫폼

업무 외 사내 학습 모임(CoP)에서 팀장을 맡아 진행하는 사이드 프로젝트. 사내 오픈소스(OSS) 자산을 SBOM으로 가시화하고, AI를 활용해 취약점을 조기 탐지하여 Slack과 이메일로 자동 알림하는 보안 플랫폼의 프론트엔드를 단독으로 설계하고 개발하고 있습니다.

Background / Problem
  • 사내에서 사용하는 오픈소스 의존성의 취약점을 수작업으로 추적하기 어렵고, 자산 현황과 위험을 한눈에 파악할 수단이 부재
  • 취약점 공개 시점과 사내 인지 시점의 간극으로 대응이 지연되는 문제
Solution / Process
  • SBOM(SPDX/CycloneDX) 기반으로 OSS 구성요소를 수집하고 자산 현황을 대시보드로 가시화
  • OSV, GitHub Advisory 등 취약점 DB와 매칭하고 AI(Claude/OpenAI API)로 영향도를 분석해 조기 탐지, Slack과 이메일로 자동 알림
  • 팀장으로서 개발 컨벤션(브랜치 전략, 커밋/PR 규칙, 네이밍)과 마일스톤을 수립하고, TypeScript와 Next.js 프론트엔드를 단독으로 설계하고 구현
Result
  • SBOM으로 사내 OSS 자산과 취약점 현황을 한눈에 파악하는 가시성 확보
  • AI 기반 조기 탐지와 자동 알림으로 취약점 대응 리드타임 단축
  • 팀장으로서 협업 규칙과 개발 프로세스를 정립하고 프론트엔드 아키텍처를 주도
  • 배운 점: 도메인 복잡도가 높은 보안 문제도 표준(SBOM)과 자동화, AI를 결합하면 실질적 운영 효율로 이어진다는 관점
